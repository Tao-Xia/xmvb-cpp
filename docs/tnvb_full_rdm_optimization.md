# 完整 3-RDM：剖析与有界工作区优化

日期：2026-10-19。基线：`c1d4b6d4`。

## 结论

完整 3-RDM 的主要耗时来自 Block2 的数值环境构建和扫描收缩。
本次实现消除后处理的六指标归一化副本，采用分片积分收缩，并提前释放原生结果。
物理公式、有限键维 MPS、独立 1/2-RDM 和误差判据保持不变。
原生输出仍有 K^6 个元素，渐近规模保持不变。

源代码已经接入 CMake 的构建/安装规则。本轮测试采用独立 worker 快照，
没有覆盖 `install-tnvb`，没有重跑 C40 或改动任何既有用户作业。

## 原生阶段剖析

在同一个 C14 总态上，D/S=200/400、16 个 Block2 线程的代表性结果：

| 阶段 | 时间 / s |
|---|---:|
| NPDM 算符图生成 | 0.017 |
| 初始数值环境构建 | 8.862 |
| 扫描收缩 | 17.448 |
| 六指标结果组装 | 0.106 |
| 其余操作 | 0.335 |
| 合计 | 26.768 |

这些分项来自驱动程序 `get_npdm` 的调用位置计时。该 Block2 pybind 构建的
多数原生方法不产生 cProfile 的 C-call 事件，因此单纯使用 cProfile
会把原生耗时归入 Python 驱动函数的 self time。
新增剖析器只跟踪这个驱动函数的源代码行，保留原生调用和收缩算法。
正常运行不启用逐行剖析。

开发时可以设置 `XMVB_BLOCK2_RDM_PROFILE` 为输出目录。
每次生成独立 JSON，保存时间分项、驱动源路径和逐行耗时；成功和异常退出时
均恢复原有 trace 状态。生产输入关键词未增加。

## 数学等价变换

令总态范数为 N，原生未归一化的六指标密度为 T。需要导出的积分收缩为

\[
C_{dc}=N^{-1}\sum_{abef}g_{faeb}T_{abcdef}.
\]

独立的粒子数收缩检验使用

\[
Q_{ijba}=N^{-1}\sum_kT_{ijkkba},\qquad
\epsilon_3=\max_{ijba}|Q_{ijba}-(N_e-2)\Gamma^{(2)}_{ijba}|.
\]

归一化在求和之后作用于 C 和 Q。独立计算的二阶密度
`Gamma^(2)` 保持原来的规范与归一化。
该变换在精确算术下等价，浮点计算仅改变求和/除法的次序。

将积分排列为 G[ab,ef]，将连续的 T 视为 T[ab,cd,ef] 后，逐个 ab 执行

\[
C_{cd}\mathrel{+}=T[ab,:,:]G[ab,:].
\]

六指标数组的 reshape 为共享存储的视图。积分排列只复制 K^4 个元素。
非连续输入采用 stride-aware einsum，避免隐式复制整个六指标数组。
输入数组保持只读语义。

## 内存与时间边界

- 完整原生输出仍占 `8*K^6` 字节；Block2 环境和临时工作区另计。
- 原来的额外六指标归一化数组被移除；后处理额外工作区降到 O(K^4)。
- 积分收缩、粒子收缩和误差检查完成后立即释放六指标输出，后续变换不再持有它。
- 消除的单个副本在 K=30、40 时分别约为 5.43、30.52 GiB。
  这表示被消除的数组大小；整个进程的峰值仍可能出现在 Block2 的扫描阶段。
- 在 K=20 的随机数组微基准中，积分收缩额外分配由约 512 MB 降至 1.29 MB，
  耗时由约 0.083 s 降至 0.016 s。该五倍比值只适用于后处理微内核。
  原生 3-RDM 的数值收缩时间没有因此下降五倍。

## 精确原生选项对照

同一 C14 MPS、同一进程、同一节点的初测：

| 原生选项 | 时间 / s | 结论 |
|---|---:|---|
| 默认 0-site / SymbolFree+Compressed / 16 线程 | 26.20 | 保留 |
| SymbolFree 不压缩片段文件 | 26.57 | 无明显收益 |
| LowMem | 27.67 | 未加速 |
| 关闭 fused contraction/rotation | 27.01 | 未加速，增加内存 |
| 1-site | 34.25 | 更慢，增加内存 |
| 8 线程 | 24.19 | 小幅收益 |
| 4 线程 | 18.82 | 值得复测 |
| SimpleTasked 块调度 | 28.00 | 未加速 |

4/16/4/16 线程交替复测得到 18.99/25.84/18.85/25.87 s。
完整六指标结果逐元素相同，4 线程较 16 线程缩短约 27%。
该结果只支持这组 C14 的配置选择；C40 的算符数量和块分布不同。
默认算法、默认线程策略、显式 `XMVB_BLOCK2_RDM_THREADS` 的语义均未修改。

原生选项的同进程 RSS 记录为累计高水位，后续选项不能据此直接比较独立峰值。

## 后续重点

优先对原生环境构建和扫描内核做块尺寸、GEMM 分布及任务调度剖析。
符号图缓存的可节省时间很小，重启 Python 的优化不会解决这一瓶颈。
更大活性空间需要单独测量数值环境、扫描、结果组装和内存峰值。
完整六指标输出的 K^6 下界仍然存在；消除这一输出需要独立验证的算法改变。
