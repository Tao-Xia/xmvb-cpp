# xmvb-cpp Standalone

This package is a standalone development snapshot of the `xmvb-cpp` path.

Current scope:

- standalone `xmvb-cpp.exe`
- C++ VB numerical kernel
- local C runtime for input parsing, molecule/basis setup, and libcint integral preparation
- runtime assets under `basis/` and `data/`

Not included as active development targets by default:

- legacy comparison tools
- legacy Fortran optimizer backend
- the full legacy `xmvb` driver build

## Build

Use a conda environment that provides at least:

- `cmake`
- `ninja`
- `eigen`
- `openblas` with LAPACKE headers
- `libxc`
- `libcint`

Then run:

```bash
./build.sh
```

If the conda environment is not activated, pass dependency roots explicitly:

```bash
./build.sh build \
  -DLAPACK_ROOT_DIR=/path/to/conda-env \
  -DLIBXC_ROOT_DIR=/path/to/conda-env \
  -DCINT_ROOT_DIR=/path/to/conda-env \
  -DEIGEN3_ROOT_DIR=/path/to/conda-env
```

This generates:

- `build/src/xmvb-cpp.exe`
- `compile_commands.json` at the workspace root
- `build/compile_commands.json`

## Smoke Test

```bash
OMP_NUM_THREADS=1 build/src/xmvb-cpp.exe src/test_molecule/F2.xmi --optimizer-backend lbfgspp
```

## VSCode and clangd

Open VSCode from an activated conda shell so `${CONDA_PREFIX}` points at the
isolated toolchain:

```bash
conda activate xmvb-cpp-dev
code .
```

The package provides:

- `.clangd` pointing clangd at `build/`
- `.vscode/settings.json` generated by `./build.sh` with an absolute clangd path
- a root `compile_commands.json` symlink refreshed by `./build.sh`
